     during Task 1 by curling the deployed instance; the shapes below are the
     v0.8.x defaults documented in danny-avila/LibreChat. -->

POST /api/auth/login
  Request:  { email: string, password: string }
  Response: { token: string, user: {...} }   // JWT in `token`, also sets refresh cookie

POST /api/ask/{endpoint}    // endpoint = "agents" for agent presets
  Headers:  Authorization: Bearer {token}
            Content-Type: application/json
            Accept: text/event-stream
  Request:  {
              text: string,
              conversationId: string | null,   // null = new conversation
              parentMessageId: string,         // "00000000-0000-0000-0000-000000000000" for first turn
              endpoint: "agents",
              agent_id: string,                // resolved from preset name
              // preset/spec selection — pass either iconURL+spec or full preset payload
            }
  Response: text/event-stream
              event: message    -> { text|delta, message: {...} }
              event: tool_call  -> { tool: string, args: object, result?: any }
              event: final      -> { responseMessage: { text, content[] } }

NOTE: LibreChat sometimes routes agent chats through /api/agents/chat or
      /api/ask/agents depending on version. Task 1 confirms the live path
      against the deployed instance before coding the request body.
