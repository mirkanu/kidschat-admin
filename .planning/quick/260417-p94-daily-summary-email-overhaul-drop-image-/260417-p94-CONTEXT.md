<decisions>
## Implementation Decisions

### AI model
- **Haiku 4.5** (`claude-haiku-4-5-20251001`) — cheapest tier, fast, handles short-conversation summarisation well. Cost target ~$0.001/summary.

### Summary tone & length
- **1 sentence + optional concerns line.** Format: `<one-sentence factual summary>. Concerns: <none | <1 short clause>>.`
- Examples:
  - `Penelope explored Roman history and worked through long-division problems, then drew a golden retriever. Concerns: none.`
  - `Sebastian asked about volcanoes and computer science, mentioned feeling frustrated with homework. Concerns: emotional/frustration content — worth checking in.`
- Max output tokens: 100 per kid (hard ceiling — Haiku will rarely use them all).

### Privacy framing
- **Paraphrase + signal sensitivity.** Never quote the kid verbatim. If kid shared emotional / friend / body / sensitive topic content, the summary signals the topic ("discussed feeling left out") without quoting words. Email goes through Resend → Gmail → potentially indexed/archived; verbatim quotes are a real privacy risk.

### Failure handling
- **Best-effort: send email with placeholder.** If the per-kid summary call fails (timeout, 5xx, rate limit), substitute `(summary unavailable today)` in that kid's slot and send the email anyway. Other kids' summaries unaffected. Stats + alerts always render.
- Implement with: try/catch per kid, 10s timeout per Anthropic call, no retries (don't risk being slow).

### Alerts section
- Source: `email_notifications` collection where `type = "safety_alert"` AND `childName = <kid name>` AND `sentAt >= 24h ago`. Match the same query as the existing notifications history page.
- Display: `Alerts: <count>` on every kid (including 0). If count > 0, append one-line AI summary of all alerts together (e.g. `Alerts: 2 — both flagged inappropriate-language pattern in same conversation about a school argument.`).

### Cost/billing routing
- Use Anthropic SDK with `ANTHROPIC_API_KEY` env (admin service env) — server-side call from the daily-summary route. Hits Anthropic billing directly (the **kidschat-admin** service's API key budget), NOT the LibreChat-facing key, NOT Manuel's tokenCredits balance. Keeps the kid-facing budget tracking clean.
- Per-day cost ceiling: with 2 kids × ~$0.001/summary + occasional alert summary ≈ < $0.01/day. Negligible.

### Claude's Discretion
- Exact wording of the AI prompt for the kid-summary (system + user message). Implementor crafts based on the tone + privacy decisions above.
- Whether to include `messageCount` in the prompt context (probably yes — helps model calibrate "active day" vs "quiet day").
- Whether to include the kid's age in the system prompt (10-14 — yes, so the model frames the summary appropriately for a parent of that age range).
- Email visual layout: how to insert Alerts + Summary into the existing per-kid card (probably as new lines below totalMessages).
</decisions>

**Anthropic prompt sketch (kid summary):**
```
SYSTEM:
You are summarising one day of chat between an AI assistant and a child (age 10-14) for the child's parent. The summary helps the parent stay informed about what their child explored, learned, or experienced.

Rules:
- Output exactly one sentence describing topics/activities, then a "Concerns:" line.
- Paraphrase — never quote the child verbatim. Words shared in chat may be private.
- If the conversation included sensitive topics (emotions, friendship struggles, body/health, fears, family conflict), name the topic gently in the Concerns line so the parent can check in. Do not quote.
- If nothing concerning, write "Concerns: none."
- Keep the whole output under 50 words.

USER:
Child: <name>
Total messages: <N>
Conversation excerpts (most recent first, truncated):
<conversations joined and truncated to ~3000 input tokens>
```

**Alert summary prompt sketch:**
```
SYSTEM:
You are summarising safety alerts triggered by an AI assistant for a parent's daily digest. Output one short sentence — what triggered the alert(s), paraphrased.

USER:
Child: <name>
Alert count: <N>
Alert details (matched patterns + brief context):
<JSON of alert meta>
```

**Verification cases for plan-time:**
- 0-message day: skip AI call entirely, render `No activity yesterday.` in summary slot
- 0-alert day: render `Alerts: 0` line, no AI call
- API failure: graceful fallback, email still sends
- Sensitive content example: prompt should produce paraphrase, not quote (test with synthetic example)
