<objective>
Two small, independent cleanup tasks for the v1 parent/kid budget system:

**(A)** Extend the midnight-UTC daily-reset cron so **parents also auto-refill** each day — mirroring the kids' behaviour. Parents get a 1M-token ceiling (via `$max`, the same idiom used for kids), so any manual drain below 1M gets topped back up, but any prior top-up above 1M is preserved. Before this change, admins were filtered out entirely (`role: { $ne: "ADMIN" }`), meaning parents only got tokens via the manual one-click top-up — easy to forget, and painful after the monthly reset.

**(B)** Rename the admin sidebar nav entry from "Settings" to "Usage Limits" — the page only holds daily/monthly cost caps + per-child overrides, and "Settings" implies broader scope than it actually has.

Purpose: Match production semantics — "parents always have budget" + "the settings page is really the usage limits page."
Output: Extended cron route + new `topUpAdminBudget` helper + renamed nav label + matching page heading, deployed to Railway, verified via live DB + cron trigger.

   ```typescript

   // Admin (parent) refill

   /**
    * Tops up an admin/parent user's balance to ADMIN_REFILL_CREDITS via $max.
    *
    * Differences vs topUpDailyBudget:
    *  - No accumulateYesterdaySpend call (admins have no balance_state / monthlyCap tracking)
    *  - No settings lookup (flat ceiling, not per-user dailyCostCapEur)
    *  - No monthly-cap gating (admins are not rate-limited by design in v1)
    *
    * Uses $max so any prior parent top-up above 1M is preserved (same idiom as kids'
    * topUpDailyBudget — atomic, single round-trip, no read-modify-write race).
    */
   export async function topUpAdminBudget(userId: string, db: Db): Promise<void> {
     const balancesCol = db.collection<BalancesDoc>("balances");
     await balancesCol.updateOne(
       { user: new ObjectId(userId) },
       { $max: { tokenCredits: ADMIN_REFILL_CREDITS } },
       { upsert: true }
     );
   }
   ```

Note: `BalancesDoc` is declared as a module-local type on line 199 — the new function lives in the same module, so no import change is needed. `ObjectId` is already imported on line 24.
