       - Auth check: `const session = await auth(); if (!session) return 401`
       - Parse body: `{ childName, alertType, matchedPattern, messageExcerpt, detectedAt, conversationId }`
       - Validate required fields — return 400 if any missing
       - Connect to MongoDB `test` db
       - **Dedup check**: Query `email_notifications` collection for existing record with same `meta.conversationId` + `meta.matchedPattern` + `sentAt` within last 1 hour. If found, return `{ sent: 0, reason: "duplicate" }` with 200 status.
       - Query admin users: `db.collection("users").find({ role: "ADMIN" }).project({ email: 1, name: 1, notification_prefs: 1 }).toArray()`
       - Filter to admins where `notification_prefs?.safetyAlerts !== false` (default true if field missing)
       - Extract email addresses, skip if empty
       - Build conversationUrl: `${getAdminUrl()}/conversations/${body.conversationId}`
       - Call `resend.emails.send({ from: getFromAddress(), to: toEmails, subject, react: SafetyAlertEmail({...}) })`
       - On success: insert record into `email_notifications` collection with `{ type: "safety_alert", sentAt: new Date(), to: toEmails, childName, resendId: data?.id, meta: body }`
       - Return `{ sent: toEmails.length, id: data?.id }`

    2. Modify `src/app/(dashboard)/alerts/page.tsx` to trigger safety alert emails:
       - The alerts page already runs `getAlertsDirectly()` which scans messages server-side and returns `SafetyEvent[]`
       - After getting alerts, add a server-side function `notifyNewAlerts(alerts)` that:
         a. Takes the top 10 most recent alerts (last 24 hours only)
         b. For each alert, does an internal fetch to `/api/notify/safety-alert` POST (or better: directly call the notification logic inline to avoid HTTP round-trip in server component)
         c. Actually — to keep it clean, extract the notification logic into a shared function `sendSafetyAlertIfNew()` in `src/app/api/notify/safety-alert/route.ts` that both the API route and the alerts page can call
         d. The dedup check in the function ensures only truly new alerts trigger emails
       - IMPORTANT: Do NOT call fetch() from a server component to its own API routes (anti-pattern). Instead, extract the core logic into a standalone async function exported from a lib file, and call it from both the API route and the server component.
       - Create `src/lib/notify-safety-alert.ts` with the core logic, import it in both places.
       - In the alerts page: after `getAlertsDirectly()`, call `notifyNewAlerts(alerts.slice(0, 10))` for recent alerts (last 24h). This runs on every page load but dedup prevents duplicate emails.
       - Wrap the notification call in try/catch — never let email failures break the alerts page rendering.
