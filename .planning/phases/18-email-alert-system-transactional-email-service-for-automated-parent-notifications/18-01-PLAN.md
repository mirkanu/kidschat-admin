1. Define `NotificationRecipient` interface:
```typescript
interface NotificationRecipient {
  _id?: string;
  email: string;           // recipient email address
  name: string;            // display name (e.g. "Mom", "Dad")
  alerts: {
    safetyAlerts: boolean;   // defaults true
    weeklyDigest: boolean;   // defaults true
    dailySummary: boolean;   // defaults true (new type, Plan 03)
    accountActivity: boolean; // defaults false (new type, Plan 03)
  };
  createdAt: Date;
  updatedAt: Date;
}
```

2. Export these functions (all use lazy `getMongoClient` import, db name "test", collection "notification_recipients"):
- `getRecipients()` — returns all recipients sorted by createdAt
- `addRecipient(email: string, name: string)` — inserts with all alerts defaulted to true (except accountActivity=false). Validate email format with simple regex. Return the inserted doc. Reject duplicate emails (check before insert, return error).
- `removeRecipient(id: string)` — delete by _id (use ObjectId)
- `updateRecipientAlerts(id: string, alerts: Partial<NotificationRecipient['alerts']>)` — $set only provided alert fields plus updatedAt
- `getRecipientsForType(type: keyof NotificationRecipient['alerts'])` — returns email[] for recipients where that alert type is true

3. Seed logic: `ensureDefaultRecipients()` — if collection is empty, query ADMIN users from `users` collection and insert them as recipients with all alerts true. This provides backward compatibility on first run.

Create `src/app/api/notification-recipients/route.ts` with:
- GET — returns all recipients (auth required via `auth()`)
- POST — body `{ email, name }`, adds recipient (auth required)
- DELETE — body `{ id }`, removes recipient (auth required)
- PATCH — body `{ id, alerts }`, updates alert prefs (auth required)

All endpoints return JSON. Use try/catch with 500 error responses.
