# Phase 15.2 — Synthetic Message Rendering in LibreChat

## The problem

Our backend (`src/lib/bonus-delivery.ts sendBonusOfferMessage`) inserts AI-authored messages directly into the `messages` collection to deliver:
1. 70% daily budget warning
2. Bonus offer ("type YES to unlock")
3. Bonus confirmation ("✓ Bonus applied")

The 15-00 inspection script confirmed that direct insertion into `messages` + updating `conversations.updatedAt` is viable at the mongo level (synthetic probe "PHASE-15-SYNTHETIC-TEST-..." rendered for Sebastian). But during plan 15-05 UAT, the production messages have repeatedly **failed to render in the kid's LibreChat UI**, despite:

- Being in the `messages` collection (confirmed by mongo query)
- Having matching `user`, `conversationId`, `parentMessageId`
- Having `endpoint: "agents"`, `model: <agent_id>`, `sender: "KidsChat Friendly Tutor"`
- Now having `content: [{type:"text", text:"..."}]` array per LibreChat's schema
- Having `attachments: []`, `expiredAt: null`, `tokenCount: 0`, `error: false`, `unfinished: false`

**Current status (commit `fd20acc`):** Still invisible after 4 rounds of schema fixes.

## What we've tried (failed)

| Round | Hypothesis | Fix attempted | Result |
|-------|------------|---------------|--------|
| 1 | Missing `parentMessageId` → siblings become branches | Added lookup of latest conversation message, used as parent | Messages still rendered as sibling branches (user saw `< >` arrows) |
| 2 | Kid can't reply YES at tokenCredits=0 | Added 15k grace token credit alongside offer | Fixed reply physics (but messages still invisible) |
| 3 | Wrong `model` field — used "agents" instead of agent ID | Set `model: agentId`, dropped `agent_id` | Still invisible |
| 4 | Missing `content[]` array — LibreChat renders typed content, not `text` | Added `content: [{type:"text", text:<template>}]`, `sender: "KidsChat Friendly Tutor"`, `attachments`, `expiredAt`, `tokenCount` | **STILL INVISIBLE — user reports "same problem"** |

## What we know for certain

1. **Direct mongo insertion works at the DB level** — 15-00's probe confirmed the synthetic message appeared in Sebastian's UI when inserted as a `messageId: "PHASE-15-SYNTHETIC-TEST-..."` doc. We need to find what that probe did differently OR what LibreChat's frontend is filtering on.

2. **Our synthetic messages are in the right conversation** — verified via mongo query (conversationId matches, user matches).

3. **`balances.tokenCredits` decrement works correctly** — Manuel + Sebastian both saw their budgets drain, and our grace credit worked (they could keep chatting at ~15k tokens).

4. **`balance_state` updates are firing** — `warnedAt70PctOn`, `activeOfferMessageId`, etc. are being set correctly. The listener logic is sound.

5. **LibreChat agent messages have a `content[]` array, not just `text`** — confirmed by side-by-side diff against a real AI message in Manuel's conversation (`conversationId 67ae8a65-...`). Our latest fix added this but didn't solve the rendering problem.

6. **The rendering bug affects every conversation we've tested** — Sebastian's "Drawing Assistance Alternatives Offered", Manuel's "Signal From Kepler Station". Consistent failure mode.

## What we DON'T know (the research questions)

### Q1 — What EXACTLY does LibreChat's frontend hydrate/filter when rendering an agent conversation?

Read the LibreChat source for how the chat UI fetches + renders messages. Specific files to inspect:
- `api/server/routes/convos.js` or `api/server/routes/messages.js` — the endpoint that returns conversation messages
- `client/src/components/Chat/Messages/` — the React components that render messages
- `client/src/data-provider/Messages/` — the data fetching hooks
- `api/models/Message.js` or `packages/data-schemas/src/schema/message.ts` — the Mongoose schema

Find:
- **Does the API route filter messages by some field before returning them?** (e.g., only messages matching the current endpoint's agent, only non-error messages, only messages with specific fields)
- **Does the frontend filter/hide messages after fetching?** (e.g., by `sender`, by `model` matching, by presence of certain fields)
- **Is there a `_meiliIndex` or search-index field required for rendering?** Real AI messages have `_meiliIndex: true` — we don't set it.
- **Does LibreChat use `content[0].type === "text"` correctly?** Or does it need `content[0].type === "think"` too?
- **Is there a hydration step** (e.g., Mongoose virtuals, post-save hooks, transform functions) that fires on normal LibreChat writes but NOT on our raw `insertOne`?

### Q2 — What did 15-00's synthetic probe do differently?

Read `scripts/mongo-inspect.ts` (the 15-00 script) and find the exact shape of the probe message it inserted. Did it match a different schema? Was the probe actually verified in the UI or did the user only confirm the DB write?

Re-read `15-00-MONGO-INSPECTION.md` and `15-00-SUMMARY.md` for the exact user confirmation wording. The current statement was "Sebastian confirmed `PHASE-15-SYNTHETIC-TEST-1775817907890` appeared" — but did he actually see it rendered, or did he see it in a branch view, or did he navigate somewhere specific?

### Q3 — Is there a DIFFERENT way to insert visible agent messages?

LibreChat has a `/api/messages` or similar endpoint used internally. Is there a server-side function we could call that handles all the required hydration? Check:
- Does LibreChat expose a "post message as agent" API that we could hit from our admin service?
- Does the `Message` mongoose model have save hooks that add required fields?
- Is there an SDK / helper function within the LibreChat packages we could import?

### Q4 — Alternative delivery mechanism?

If direct insertion is unsolvable, what other channels exist for delivering a system message to a kid's LibreChat UI?
- LibreChat `banners` collection (we saw it in the 15-00 inspection) — could we insert a banner that shows at the top of the chat?
- LibreChat notifications (if any)?
- An admin-side "send message" proxy that calls LibreChat's actual message-post API?
- The agent's system prompt ("When user types YES after seeing a budget message, reply...") — fragile but predictable?
