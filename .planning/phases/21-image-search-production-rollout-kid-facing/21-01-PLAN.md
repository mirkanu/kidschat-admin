<objective>
Harden the kidschat-image-search-mcp Railway service with four production-gate additions that do NOT exist yet in Phase 20's POC code, plus close the 20-05 C-2 zero-result quirk:

1. **Query blocklist** (D-8 Layer 2, SAFETY-01 defense-in-depth): static regex list in a new `blocklist.ts` that rejects banned terms BEFORE calling Openverse. Returns `{images:[], error:"blocked_query"}` to the agent.
2. **Domain blocklist** (SAFETY-01): a `BLOCKED_DOMAINS` regex set applied to `source_domain` AFTER Openverse response — filters results whose `source_domain` matches before they reach the agent.
3. **Hotlink proxy** (SEARCH-06): a new `/proxy?u=<base64url>` HTTP route that streams image bytes server-side for thumbnails whose upstream blocks hotlinking (observed ~5–10 % rate in Phase 20 UAT Q1). Openverse provider rewrites thumbnail URLs to go through this proxy.
4. **Per-user search-count enforcement** (SEARCH-07): MCP calls the new kidschat-admin endpoint `POST /api/image-search/quota` with the LibreChat-forwarded userId and a shared secret. If admin returns `allowed=false`, tool returns `{images:[], error:"quota_exceeded"}` without calling Openverse.
5. **Zero-result quirk mitigation** (20-05 C-2, SEARCH-02): when Openverse returns 0 results for a multi-token query, retry once with modifier words stripped. Lifts the observed 40%-zero-result rate on normal kid queries without requiring OAuth quota upgrade.

Purpose: Close all Phase 21 MCP-level requirements so the tool boundary is the strongest safety gate. Everything else (schema, UI, oversight) builds on top.
Output: Extended MCP service deployed to Railway `kidschat-image-search-mcp` with the five new layers live; blocklist + quota + retry gating verified via curl against the deployed endpoint.
</objective>
