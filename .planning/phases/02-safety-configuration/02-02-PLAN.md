<task type="auto">
  <name>Task 2: Redeploy LibreChat on Railway and confirm config loads</name>
  <files></files>
  <action>
Trigger a Railway redeploy of the LibreChat service so it fetches the new YAML from the Gist at startup.

Step 1 — Redeploy:
```bash
cd /data/home/KidAI && railway redeploy --yes
```

If the command fails because no service is selected, specify the service explicitly (LibreChat service name is "LibreChat" or similar — check with `railway status`):
```bash
railway service
# select the LibreChat service
railway redeploy --yes
```

Step 2 — Wait for startup. LibreChat takes approximately 60-90 seconds to restart. After triggering redeploy, wait then tail logs:
```bash
sleep 90 && railway logs --tail 50
```

Step 3 — Verify config loaded. Look for this line in logs:
```
Custom config file loaded
```

If you see instead:
- `Custom config file missing or YAML format invalid` — the YAML pushed to Gist has a syntax error. Do not proceed to Plan 03. Re-validate the YAML locally with `python3 -c "import yaml; yaml.safe_load(open(...))"` and fix the error.
- No mention of config — the Gist URL may have CDN cache delay. Wait 60 more seconds and check logs again after another redeploy.

Step 4 — Verify the app is accessible:
```bash
curl -s -o /dev/null -w "%{http_code}" https://librechat-production-bff2.up.railway.app/
```
Should return 200 or 302 (login redirect). Any 5xx means the service did not start successfully.

Step 5 — Verify model specs are active via the config API:
```bash
curl -s "https://librechat-production-bff2.up.railway.app/api/config" | python3 -c "import sys,json; data=json.load(sys.stdin); specs=data.get('modelSpecs',{}); print('enforce:', specs.get('enforce')); print('specs count:', len(specs.get('list',[])))"
```
Should show `enforce: True` and `specs count: 4`.
