## Per-Change Rationale

### 1. HARDEN-MCP-01 — Disable MCP Server Add UI

**Config key:** `interface.mcpServers`
**Value applied:** `{use: false, create: false, share: false, public: false}`

MCP (Model Context Protocol) servers grant arbitrary tool capabilities to AI agents. A child who could add an MCP server could wire the agent to external APIs, file system access, browser automation, or other tools that completely bypass the safety rules baked into the agent's system prompt. The `create: false` flag removes the "Add MCP Server" dialog from the UI. The `use: false` flag additionally prevents using any globally configured MCP servers. Belt-and-suspenders: even if a server is pre-configured server-side, kids cannot invoke it through the UI.

Schema verified in `packages/data-provider/src/config.ts` — the `mcpServersSchema` object schema with `use`, `create`, `share`, `public` boolean fields is fully supported and will not cause ZodError.

### 2. HARDEN-MARKETPLACE-01 — Disable Agent Marketplace

**Config key:** `interface.marketplace.use`
**Value applied:** `false`

The Agent Marketplace allows browsing and installing community-created agents. Community agents have un-reviewed system prompts, tools, and rules — they could expose harmful content, bypass safety guardrails, or grant capabilities the platform didn't intend. The marketplace was already disabled in the schema defaults (`use: false`), but was not explicitly set in our live config. This change makes the intent explicit and protects against any future default change in LibreChat upgrades.

Schema verified in `packages/data-provider/src/config.ts` — `marketplace: z.object({ use: z.boolean().optional() })` is a supported schema field.

### 3. HARDEN-DELETE-01 — Block Conversation Delete (ACCEPTED LIMITATION)

**Config key:** NONE — no config toggle exists in LibreChat v0.8.4
**Action taken:** None (no config change applied)

An exhaustive search of `packages/data-provider/src/config.ts` (2073 lines) and `librechat.example.yaml` (609 lines) found no config toggle for disabling conversation deletion. The LibreChat v0.8.x interface schema does not contain:
- `interface.deleteConversations`
- `permissions.USER.conversations.delete`
- `features.conversationDelete`
- Or any equivalent field

**Why no workaround was applied:**
- Do NOT fork LibreChat to add the feature — scope creep, maintenance burden
- Do NOT inject CSS hacks — brittle, easily bypassed by a curious 14-year-old in browser devtools
- Do NOT invent a YAML key that isn't in the schema — LibreChat's ZodSchema will throw on startup (observed in Phase 2 Plan 03)

**Risk assessment:** Low. Even if Sebastian deletes a conversation from the LibreChat sidebar, the admin dashboard retains a copy via the separate MongoDB collection that the admin app queries. Parent oversight is maintained. The delete is a UI convenience, not a data-erasure operation from the admin's perspective.

**Follow-up:** If this becomes a priority, the correct fix is a LibreChat upstream feature request or a server-level middleware that intercepts the delete endpoint for non-admin users.

### 4. POLISH-ICONS-01 — Distinct Preset Icons

**Config key:** `modelSpecs.list[*].iconURL`
**Values applied:** 4 lucide SVG URLs from unpkg CDN

Lucide icons via `https://unpkg.com/lucide-static@latest/icons/{name}.svg`:
- Friendly Tutor → `graduation-cap` — learning/school context; immediately recognizable for academic help
- Casual Buddy → `smile` — friendly/relaxed tone; emoji-like familiarity for the casual mode
- Balanced Helper → `scale-3d` — balance/equilibrium; clear visual metaphor for the middle-ground preset
- Standard Formal → `briefcase` — professional/formal context; business-like icon signals structured responses

All 4 URLs return HTTP/2 200 (after unpkg redirect). The lucide-static package is ISC-licensed; unpkg is a public CDN with no auth required and CORS enabled for browser requests.

Before this change, all 4 presets displayed the same default LibreChat agent icon, making it hard for younger children (Penelope, 12) to visually distinguish which mode they're in.
