## Decisions Made

### $max operator (not $set)
`$max: { tokenCredits: credits }` is atomic: if the stored value is already >= credits (parent topped up), MongoDB leaves it alone. If it's less (depleted by child use), MongoDB sets it to credits. This satisfies both constraints in one operation with no race condition, no schema change, and no extra read.

### displayedMonthlySpendEur vs monthlySpendEur split
- `monthlySpendEur` (stored) = cumulative spend incremented by the daily-reset cron each midnight UTC — DB ground truth
- `displayedMonthlySpendEur` (computed) = `monthlySpendEur + max(0, dailyCap - remainingEur)` — adds today's partially-spent budget for live display
- Avoids double-counting: today's partial spend is never written to `monthlySpendEur` during the day; it gets accumulated at the NEXT midnight when it becomes "yesterday"

### Monthly cap enforcement choke point
Enforcement happens at the daily-reset cron (midnight UTC), not mid-conversation. `topUpDailyBudget` checks `displayedMonthlySpendEur >= monthlyCostCapEur` and skips the token refill if true, but still advances `lastDailyReset` to prevent re-evaluation loops. This is the one atomic enforcement point — no polling, no mid-conversation checks needed.
