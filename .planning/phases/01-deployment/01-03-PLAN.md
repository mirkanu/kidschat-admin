<task type="checkpoint:human-action">
  <name>Task 2: Create the GitHub Gist and set CONFIG_PATH in Railway</name>
  <files>N/A — GitHub and Railway dashboard actions</files>
  <action>
    Guide the user to create a public GitHub Gist with the YAML from Task 1, capture the filename-specific raw URL, set CONFIG_PATH in Railway, and confirm LibreChat reloads without YAML errors.
  </action>
  <what-to-do>
    Step A — Create the GitHub Gist:
    1. Go to https://gist.github.com (log in with your GitHub account)
    2. In the filename field, type exactly: librechat.yaml
    3. Paste the YAML content from Task 1 into the body
    4. Set the Gist to PUBLIC (this file contains no secrets, so public is correct)
    5. Click "Create public gist"
    6. On the created Gist page, click "Raw" to view the raw file URL
    7. CRITICAL: Copy the raw URL. It must follow this format exactly:
       https://gist.githubusercontent.com/YOUR_USERNAME/GIST_ID/raw/librechat.yaml
       The URL MUST end with /raw/librechat.yaml — including the filename. Do NOT use a URL that omits the filename (the version-agnostic format is unreliable per PITFALLS.md Pitfall 5).

    Step B — Security check (do this before setting CONFIG_PATH):
    8. Open the raw URL in an INCOGNITO browser tab (not logged into GitHub)
    9. Verify: you can see the YAML content and there are NO strings starting with sk-ant- or any other credentials
    10. Close incognito tab

    Step C — Set CONFIG_PATH in Railway:
    11. In Railway dashboard, go to your LibreChat service → Variables tab
    12. Add a new variable: CONFIG_PATH = [paste the raw Gist URL from step 7]
    13. Save. Railway will auto-redeploy the LibreChat service.
    14. Wait for the LibreChat service to show healthy/green status (1-3 minutes)
    15. Check the LibreChat service logs (Railway → LibreChat service → Logs tab):
        - GOOD sign: "Custom config loaded" or "Config file loaded successfully"
        - BAD sign: "Custom config file missing" or "YAML format invalid" — if you see this, paste the error here
  </what-to-do>
  <verify>Railway redeploys successfully, logs show config loaded without YAML errors, incognito check confirms no credentials in Gist</verify>
