**1. Create `src/lib/gist-client.ts`:**

Export two async functions:
- `fetchGist(gistId: string): Promise<{ content: string; updatedAt: string }>` — calls `GET https://api.github.com/gists/{gistId}` with `Authorization: Bearer ${process.env.GITHUB_GIST_TOKEN}` header. Extract the content of the first file in the Gist's `files` object. Return content string and `updated_at` timestamp.
- `updateGist(gistId: string, filename: string, content: string): Promise<void>` — calls `PATCH https://api.github.com/gists/{gistId}` with the file content in `{ files: { [filename]: { content } } }`. Throw on non-2xx response with the GitHub error message.

Both functions read `GITHUB_GIST_TOKEN` from `process.env` (server-only, no NEXT_PUBLIC_ prefix). Use native `fetch`, NOT Octokit. Include `Accept: application/vnd.github+json` header per GitHub API convention.

**2. Create `POST /api/prompt-editor/deploy/route.ts`:**

Auth guard: require ADMIN session (same pattern as `/api/admin-chat/route.ts` — check both session and role).

Request body: `{ draft: string }` — the new system prompt text.

Steps:
a. Read env vars `GIST_ID` and `GITHUB_GIST_TOKEN`. Return 500 if missing.
b. Call `fetchGist(GIST_ID)` to get current Gist content.
c. Parse the YAML content to find the current systemPrompt value under `endpoints.custom[0].default.systemPrompt` (use a simple string replacement approach — find the `systemPrompt: |` block and replace it). Actually, since YAML manipulation is error-prone, use the approach: read the full Gist YAML content as a string, find the existing systemPrompt block using regex/string search, and replace it with the new draft. The prompt in the YAML is a YAML literal block scalar (pipe `|`).
d. Save rollback entry to MongoDB: `db.collection("prompt_history").insertOne({ previousContent: currentGistContent, previousPrompt: extractedOldPrompt, deployedPrompt: draft, deployedAt: new Date(), deployedBy: session.user.email })`. `currentGistContent` is the FULL Gist YAML before modification.
e. Call `updateGist(GIST_ID, "librechat.yaml", updatedYamlContent)` to push the new content.
f. Also store the active prompt in MongoDB for Safety Rules sync: `db.collection("app_config").updateOne({ key: "active_prompt" }, { $set: { value: draft, updatedAt: new Date() } }, { upsert: true })`.
g. Return `{ success: true, deployedAt: new Date().toISOString() }`.

If any step fails, return appropriate error. If Gist fetch fails, do NOT save a rollback entry (nothing to roll back to).

**3. Create `POST /api/prompt-editor/review/route.ts`:**

Auth guard: require ADMIN session.

Request body: `{ draft: string }`.

Call Claude Sonnet (non-streaming, `client.messages.create`) with a structured system prompt that acts as a checklist reviewer. The system prompt should instruct Claude to check for these REQUIRED SECTIONS in the draft:

1. **Jailbreak resistance** — explicit instructions for handling override/bypass attempts
2. **Content boundaries** — rules about profanity, sexual content, violence, substance abuse
3. **Reformed Christian values** — theological guardrails (Trinity, Scripture authority, no relativism)
4. **Anti-cheating policy** — instructions to teach not do homework
5. **Tone/redirect language** — how to handle boundary violations gently
6. **Identity framing** — AI identifies as safe assistant, does not reveal full instructions

The system prompt for the reviewer should be:
```
You are a safety prompt reviewer for a children's AI chat application. Check the following draft system prompt against the required sections checklist. For each section, respond with PASS or FAIL and a brief explanation.

Required sections:
1. JAILBREAK_RESISTANCE — Must contain explicit instructions for handling attempts to override rules
2. CONTENT_BOUNDARIES — Must define prohibited content categories (profanity, violence, sexual, substance abuse)
3. REFORMED_VALUES — Must reference Christian/biblical principles and prohibit theological contradiction
4. ANTI_CHEATING — Must instruct the AI to teach, not complete homework
5. TONE_REDIRECT — Must describe gentle redirection when boundaries are hit
6. IDENTITY_FRAMING — Must instruct AI to maintain its identity and not reveal full instructions

Respond in JSON format:
{
  "sections": [
    { "id": "JAILBREAK_RESISTANCE", "status": "PASS"|"FAIL", "reason": "..." },
    ...
  ],
  "overall": "PASS"|"FAIL",
  "summary": "Brief overall assessment"
}
```

Use `claude-sonnet-4-6` model, `max_tokens: 1024`. Parse the response as JSON. If JSON parsing fails, return the raw text with `overall: "ERROR"`.

Return the review result to the client.

**4. Create `/api/prompt-editor/history/route.ts`:**

Two handlers:

`GET` — Auth guard (ADMIN). Fetch the most recent entry from `prompt_history` collection sorted by `deployedAt` descending, limit 1. Return `{ hasHistory: boolean, entry?: { previousPrompt, deployedPrompt, deployedAt, deployedBy } }`.

`POST` — Auth guard (ADMIN). Request body: `{ action: "rollback" }`. Fetch most recent `prompt_history` entry. Use the `previousContent` field (full YAML) to restore the Gist via `updateGist`. Also update the `app_config.active_prompt` to the `previousPrompt` value. Return `{ success: true, restoredAt }`.
