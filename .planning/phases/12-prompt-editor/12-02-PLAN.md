**2. Create `src/app/(dashboard)/prompt-editor/page.tsx`:**
Server component. Import `SYSTEM_PROMPT` from `@/lib/system-prompt`. Also query MongoDB for the `app_config` collection to check for an `active_prompt` entry. If found, use that as `initialPrompt`; otherwise fall back to `SYSTEM_PROMPT`. Auth guard with `auth()` + redirect to `/login` if not authenticated. Pass `initialPrompt` and `hardcodedPrompt` (the SYSTEM_PROMPT constant) as props to `PromptEditorClient`.

```typescript
// Pseudocode:
const client = await clientPromise;
const db = client.db("test");
const activePromptDoc = await db.collection("app_config").findOne({ key: "active_prompt" });
const initialPrompt = activePromptDoc?.value || SYSTEM_PROMPT;
return <PromptEditorClient initialPrompt={initialPrompt} hardcodedPrompt={SYSTEM_PROMPT} />;
```

**3. Create `src/app/(dashboard)/prompt-editor/prompt-editor-client.tsx`:**

`"use client"` component. Props: `{ initialPrompt: string; hardcodedPrompt: string }`.

**State management:**
- `draft: string` — initialized from `initialPrompt`
- `reviewResult: ReviewResult | null` — result from AI review
- `isReviewing: boolean` — loading state for review
- `isDeploying: boolean` — loading state for deploy
- `showDeployModal: boolean` — confirmation modal
- `deploySuccess: { deployedAt: string } | null` — post-deploy state triggering redeploy banner
- `rollbackEntry: RollbackEntry | null` — loaded on mount from GET /api/prompt-editor/history
- `isRollingBack: boolean`

**Layout (two-column on desktop, stacked on mobile):**

Left column (editor area):
- Page heading: "Prompt Editor" with subtitle "Edit, review, and deploy the system prompt"
- `<Textarea>` with monospace font, full width, min-height ~400px, value bound to `draft`. Use `font-mono text-sm` classes.
- Character count below textarea
- Button row below textarea:
  - "AI Review" button (purple/violet accent) — calls `POST /api/prompt-editor/review` with `{ draft }`. While loading, show spinner. On success, populate `reviewResult`.
  - "Test in Sandbox" button (secondary) — navigates to `/test-mode` passing the draft. Use `sessionStorage.setItem("draft-prompt", draft)` before navigation so the test mode can pick it up. (The test-mode-client.tsx will need to be aware of this in a future update, but for now just store it and open test-mode in a new tab via `window.open("/test-mode", "_blank")`).
  - "Deploy to Gist" button (destructive/red accent) — DISABLED if draft === initialPrompt (no changes). On click, set `showDeployModal = true`.
  - "Reset" button (ghost) — resets `draft` to `initialPrompt`, clears review results.

Right column (review panel + status):
- If `reviewResult` exists: render a Card titled "AI Review Results" with:
  - Overall status badge: green "PASS" or red "FAIL"
  - Summary text
  - Checklist of sections, each with a green checkmark (PASS) or red X (FAIL) icon, section name, and reason
- If `deploySuccess` exists: render a persistent amber/yellow banner Card:
  - Icon: `AlertTriangle`
  - Text: "System prompt deployed to Gist. Redeploy LibreChat to activate changes for children."
  - This banner persists until the page is refreshed/navigated away
- If `rollbackEntry` exists and `rollbackEntry.hasHistory`: render a "Rollback" section:
  - Text: "Previous version from {date}"
  - "Restore Previous Version" button (outline). On click, calls `POST /api/prompt-editor/history` with `{ action: "rollback" }`. On success, reload the page (or reset draft to `rollbackEntry.previousPrompt` and clear deploy state).

**Confirmation Modal (showDeployModal):**
Use shadcn `AlertDialog`.
- Title: "Deploy System Prompt?"
- Description: "This will update the system prompt in GitHub Gist. The change will take effect after LibreChat is redeployed. The current version will be saved for rollback."
- Cancel button and "Deploy" button (destructive variant).
- On confirm: call `POST /api/prompt-editor/deploy` with `{ draft }`. On success, set `deploySuccess`, refresh rollback entry. On error, show toast via sonner.

**On mount:**
- Fetch `GET /api/prompt-editor/history` to check for rollback availability, set `rollbackEntry`.

**Error handling:**
- All fetch calls wrapped in try/catch
- Errors shown via `toast.error()` from sonner (already in DashboardShell)
